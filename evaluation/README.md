# Evaluation of Topic Grouper (ECIR 2019)

This Maven module re-runs the evaluation of the paper with publicly available data only and
writes the results as CSV files. Plotting is separate (see `tikz/plots.tex`).

## Quick start

```sh
evaluation/scripts/run-all.sh --quick     # download data, run scaled down experiments (minutes)
evaluation/scripts/run-all.sh             # the full setup of the paper (hours to days, needs several GB of RAM)
```

Requirements: Java 8+, Maven, `curl`, `tar`, `gunzip`. `run-evaluation.sh` first installs the library from
the parent directory (`mvn install -DskipTests`) and then builds this module. The result is
`target/topic-grouper-evaluation.jar` which can also be run directly:

```sh
java -Xmx8g -jar target/topic-grouper-evaluation.jar [experiments] [--data DIR] [--out DIR] [--quick]
```

`experiments` is a comma separated list of `perplexity`, `twc-series`, `classification`, `performance`
(default: all). An experiment whose data set is not in the data directory is skipped with a message.

## Data

| Data set | Used for | Source |
|---|---|---|
| TWC (synthetic) | perplexity, series, performance | generated by the code, nothing to download |
| NIPS | perplexity | UCI bag of words (`archive.ics.uci.edu`) |
| Reuters-21578 | classification, performance | Distribution 1.0 (ModApte split) |
| 20 Newsgroups | classification, performance | `20news-18828` (`qwone.com`) |

`scripts/download-data.sh [DIR]` fetches everything into `evaluation/data`.

Not part of this module because they are not (easily) public: the AP corpus extract used in the paper, OHSUMED and the
retail data sets (Ta-Feng, US supermarket). The original code for them is still in `src/test/java` of the library
(see below).

## Experiments and output files

All files are `;` separated with a header line, written into `results/`.

| File | Columns | Content |
|---|---|---|
| `perplexity-twc.csv`, `perplexity-nips.csv` | `method;topics;perplexity;alphaConc` | held out perplexity (document completion, left-to-right estimate) of Topic Grouper (`tg`, with the Dirichlet concentration `alphaConc` optimized on training data), LDA (`lda`), PLSA (`plsa`, synthetic data only) and the `unigram` baseline |
| `twc-docs.csv` | `docs;method;perplexity;errorRate` | synthetic corpus, 4 topics, growing number of documents; `errorRate` is the share of words assigned to a wrong true topic |
| `twc-alpha.csv` | `alpha1;method;perplexity;errorRate` | synthetic corpus, 4 topics, growing skew of the topic distribution |
| `classification-reuters.csv`, `classification-20ng.csv` | `method;topics;microAvg;macroAvg;lambda` | accuracy of naive Bayes on topics from Topic Grouper (`tg-nb`, `tg-nb-smoothed`), tf-idf on topics (`tg-tfidf`), LDA (`lda-nb`) and on selected words (`vocab-ig`, `vocab-df`) |
| `performance-*.csv` | `solver;docs;avgSeconds;stdDevSeconds;avgWords` | run time of the heap based (`ehac`) and the low memory (`lowmem`) solver over the number of documents |

`--quick` shrinks topic grids, Gibbs iterations and repetitions (see `Settings.java`), the numbers are then
only meant as a smoke test.

## Plots

`tikz/plots.tex` contains pgfplots figures that read the CSV files from `../results`:
`cd tikz && pdflatex plots.tex`. Any other tool (R, pandas, gnuplot) can use the CSV files as well.

## Notes and deviations from the original code

* The legacy experiment code of the paper (`src/test/java/org/hhn/topicgrouper/paper`, `eval`, `demo`) needs a
  LingPipe 3.9.3 build which is not on Maven Central (see `bin/updateRepository.sh`). It is excluded from the
  library's default test build and can be compiled with `mvn -Plegacy-experiments`. This module uses the
  LingPipe 4.1.2 tokenizers from Maven Central and its own small Reuters-21578 reader (same ten categories,
  one document per category, like the original parser), so token counts may differ slightly from the paper.
* Vocabularies with more than 2500 words are processed with `LowMemTopicGrouper` instead of the memory hungry
  `EHACTopicGrouper` (same result, slower). 20 Newsgroups with the full topic grid takes long.
* LDA uses `alpha = 50/topics` as concentration (as in the original perplexity code) and `beta = 0.1`; fold-in classification
  uses `alpha = 50` (as in the original classification code).
* `LDAGibbsSampler` writes `alphabetalog.log` into the working directory (the scripts run in `evaluation/`).
